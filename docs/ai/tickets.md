# Types of tickets
Use these definitions for creating tickets, if no type fits your scenario, bring it up to the human

- Discovery [discovery]: a session where we plan a big or uncertain feature with /tlc-discover
- UI [ui]: a session with Claude Design to brainstorm and design UI big features from discovery.
- Feature slice [slice]: chunks of big work broken down during the discovery session. Each chunk needs to be planned with /tlc-plan.
- Spike [spike]: a session to test something and gain information to backup future decisions. May result in code, maybe not.
- Risk [risk]: something found during development that needs to be fixed to improve resilience, security, performance, etc.
- Bug [bug]: plain old bug registered just so we don't leave it behind.
